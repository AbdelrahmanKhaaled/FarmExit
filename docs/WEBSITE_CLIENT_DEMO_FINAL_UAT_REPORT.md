# Website client demo final UAT

Date: 2026-10-22. Local development database `farmexit`, verified against the machine's MySQL hostname. Website http://localhost:3000, API http://127.0.0.1:4001/api/v1, existing Dashboard http://localhost:3002. Port 4000 was not used.

## Acceptance decision

**A limited, verified demonstration is available; full Website acceptance is NOT granted.** Farm ownership, private sale/rent review requests, professional verification, published farm browsing, saved listings, inquiries, tracking, and staff-mediated communication were exercised with real local API responses and persisted synthetic data. Confirmed defects in session refresh, login return paths, navbar session state, and message loading were fixed and reverified.

Purchase/co-purchase **submission remains NOT TESTED**: no approved, writable, published listing belongs to the isolated identities. The existing proposal transaction updates its parent listing request even before creating the proposal. Using an unrelated published record would violate the mutation restriction. No listing was published to work around this. Registration/profile completion also lacks a fresh approved identity; existing identities already have completed profiles.

Management/Partnership public publication and Management applications remain **BLOCKED BY EXISTING API**. This task does not claim they are public marketplaces ready for applications.

## Confirmed defects and fixes

1. **P1: messages did not load.** Client requested `pageSize=100`; real API returned 400 (`pageSize must not be greater than 50`), and browser displayed Could not load messages. `messages-client.ts` now requests supported 50-item pages until total is reached; failure of any page does not present a partial history as complete. Real browser history, refresh and live replies succeeded afterwards.
2. **P1: session refresh middleware never matched normal pages.** Incorrect JS escape in proxy matcher compiled to `.*..*` and excluded extensionless routes. Correctly escaped literal dot restores proxy execution. Before fix, deleting only access cookie sent a valid refresh session to sign-in. After fix, the real refresh rotated cookies and kept the profile authenticated. Root locale routing regression passes.
3. **P1: deep protected login lost its destination.** Parent portal layout redirected to generic `/my` before the individual page's existing guard. It now renders the authenticated shell only for a session and lets each guarded page redirect using its route. Every current portal page was checked to have its own session/profile guard. EN/AR farm-create redirects and actual OTP return succeeded. No Backend authorization was removed.
4. **P1: stale navbar account after logout.** Focus revalidation obtained 401, but the hook returned initialUser unconditionally. It now returns updated session state. Confirmed actual Sign in link after logout/focus and denial of replayed cookies.
5. **Misleading unsupported filter controls.** Disabled Hero Activity, unsupported Management facets, and header range selects containing only placeholders. Existing supported Area/Budget ranges and sidebar filters remain enabled. No unsupported filters/API features were introduced.

Changed production files: `web/src/proxy.ts`, `web/src/app/[locale]/my/layout.tsx`, `web/src/components/layout/use-navbar-session.ts`, `web/src/features/my-messages/messages-client.ts`, `web/src/features/home/HeroSearch.tsx`, `web/src/features/marketplace/MarketplaceSearch.tsx`. React checklist reviewed: hooks remain unconditional, state reflects server revalidation, disabled controls use native disabled semantics, protected pages retain per-page guards, and dependent message pages are fetched in sequence. No Dashboard or Backend business module was changed in this task.

## Browser environments and runtime limitations

- EN desktop 1440×1000: forms, confirmations, owned/public detail, feedback, read-only states, profile, lists and message threads exercised.
- AR desktop: `/ar/farms`, `/ar/farms/demo-dash-10-sale`, `/ar/my`, `/ar/my/requests`, `/ar/my/professional/verification/770` returned 200 and `html dir=rtl`; localized sign-in/protected redirects verified.
- Representative mobile 390×844: Arabic inquiry messages and owned farm, English marketplace. Measured document scroll width 390 equals viewport 390. Screenshots inspected. This is not an exhaustive device/browser accessibility audit, nor every mutation repeated in both languages.
- Development Next generated malformed `prerender-manifest.json` repeatedly during active browsing, causing 500s. A stopped-server cache move preserved `web/.next/dev-uat-before-restart`; rebuilding development cache alone did not resolve it. Final live acceptance ran on the successful local **production build** with `next start --port 3000`, not on a claimed fixed dev server. Development-mode manifest corruption remains a tooling/runtime limitation and should not be used for the client walkthrough.
- Production realtime requires the existing public origin configuration at **build time**. An initial production build without it correctly had realtime disabled; it was rebuilt with `NEXT_PUBLIC_FARMEXIT_REALTIME_ORIGIN=http://127.0.0.1:4001`. Final browser Socket.IO delivery succeeded. No fallback to port 4000 was added.

For the same local demo, build with that public origin environment setting, then run `npm --prefix web run start -- --port 3000`. Keep the API on 4001. Website production server is left running on 3000; the existing API and Dashboard listeners remain available.
