## Implemented behavior

- Owner seven-step and individual/company five-step task layouts reuse `TaskFrame`, `WizardCard`, `WizardDisclosure`, private `RequestDocumentsPanel`, status and tracking components. Desktop uses 296px / flexible 656px / 264px columns with 48px gaps inside the existing 1312px container. Tablet uses form plus information cards; mobile uses the existing compact step menu. Actions remain in document flow.
- Objective is a radio group; accepted partner types are checkboxes; contribution/background choices retain their reference shape but are disabled when no supported save contract exists. No unsupported value is submitted under another field name.
- Controlled drafts preserve supported values, including blanks, across step changes and reload/edit. Creation updates the existing detail URL. Save & exit waits for the API. Submit saves current edits before requesting review. Duplicate action guards, hydration readiness, real loading/error feedback, selected-document protection and unload protection prevent false success or discarded input.
- Company kind becomes immutable after creation, matching the existing contract. Blank company drafts can advance to the details step without an invalid empty update. Actual account data is shown only to its authenticated user.
- Review, private document upload/download/version history, changes-requested comments, correction and resubmission use existing APIs. Successful submission is shown only after the API returns `underFarmExitReview`.
- Lists show actual private rows, status badges, filters and edit/track links. No applications, documents, ratings or roles are fabricated.
- Cash, installment, exchange, mixed and co-purchase proposal integrations remain intact. Proposal forms reuse shared selects, retain conditional sale-term eligibility and percentage validation, guard repeated requests, and keep values on errors. Proposal notes can be cleared when editing. Existing FarmExit-mediated contact actions remain intact.
